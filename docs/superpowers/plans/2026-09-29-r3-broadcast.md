**Goal:** Put R3 — one MOVX that reads the scratch source once and writes the same x into the XWIN of all four channels — on silicon as its own signed-off bitstream (R1 + R2 + R3 + the BM1 counters), with tokens identical to the shipped reference at every rung, R1 and R2 unmoved, and the decode step measured against a prediction committed first.

**Architecture:** Software first, shared by both forms (ISA text → validator → reference model → cost model → the pass's real broadcast node and the r3 streams → the host's device-keyed admission → the chip-TB prediction), each TDD with its own gate doc. Then the RTL of form (a): `seq_0` drives one new aclk-only point-to-point push port per channel (32-bit word, 12-bit word index, valid), each `mvchan` takes it as a third source on its XWIN FIFO mux with AXI-Lite still winning, and a broadcast word is pushed only when all four channels have room (lockstep). Then the chip TB (rung 1 cycle-identical on the new top — the round's first TB-top change — coverage through the real engine with a mutant, then the r3 streams against the prediction), then one incremental build against R2's signed-off routed checkpoint, then one board session under the user's per-bitstream load ruling.

**Tech Stack:** SystemVerilog (Verilator 5.020 `-Wall --timing`), Python (`ref/` models, `sw/` host tools; uv venvs), Vivado 2024.2 on snoke, BCU-1525 on snoke via the CHARTER safe JTAG flow; the campaign wrapper `evidence/qwen9b/sr/sr_run.sh` (this campaign keeps the round's evidence directory `evidence/qwen9b/sr/` and its wrapper, with disjoint log blocks, below).

### Standing hazards this plan inherits

- **A broadcast is fail-closed on every pre-R3 bitstream.** MOVX `flags[7:4]` ≥ 4 faults err 0x05 today (`rtl/seq_unit.sv:798-800`), on build_041/042/044/045 alike, before any word moves (spec §1.3). The device-keyed validation refuses it before upload anyway; the RTL fault is the second line.
- **R2 is NOT fail-closed on an old bitstream** (`docs/SEQ_ISA.md` §B17.2, FORWARD COMPATIBILITY): an r3 stream also carries bank fields, so its admission on an R1-only or R2-only device must fail on the broadcast record **by the validator**, never by reaching the RTL.
- **The margin R3 must fit into is one placement's.** R2 signed off at design WNS +0.004 (the XDMA GTY TXOUTCLK → aclk pair), aclk +0.012 (ATTN_DSP), u_attn +0.012, u_dn +0.015, the xline CE cone +0.032, UI +0.026 … +0.064, `seq_0` +0.247 — and closed only inside route_design's in-router re-place from a post-place WNS of −0.791 (`evidence/qwen9b/sr/SR14_R2_BUILD.md` §2.2, §2.3). On the ship ATTN_DSP sat at exactly 0.000 and every worst family path is SLR0 → SLR0 (`evidence/qwen9b/g5/G5D_TIMING.md:1052-1059`); form (a)'s new path crosses into SLR0 to `mvchan_0` (`evidence/qwen9b/g5/G5D_TIMING.md:1062-1066`). SLLs are not the constraint (same lines). Any netlist change re-opens the whole timing gate.
- **The x-FIFO mux is shared with two live legs.** AXI-Lite wins unconditionally and the burst leg holds for the AXI-Lite commit cycle (`rtl/matvec_chan.sv:95-99`, `rtl/matvec_chan.sv:256-263`, `rtl/matvec_chan.sv:587-598`); the burst leg's COMMIT CONTRACT — a word is in the FIFO on the edge that raises BVALID — is what orders MOVX before the next MVGO's doorbell (`rtl/matvec_chan.sv:100-110`). The push leg needs its own commit contract (R3-8).
- **The golden generator carries its own validator and executor** (`tb/scripts/gen_seq_unit_vectors.py`, a twin of `ref/seq_format.py` / `ref/seq_model.py`): every semantic change lands in both.
- **The r3 `.e4` streams and chat images are gitignored and regenerable**: a task that consumes one re-checks its FULL sha256 against the log that generated it first.
- **The census's R3 is an optimistic model** (siblings free; spec §6 item 4): the latest-of-four dependency part costs 0 cycles when modelled, but bank forcing is inferred, not modelled, and the one-window pricing of a form-(a) broadcast is the spec's estimate (`evidence/qwen9b/sr/SR16_R3_DECISION.md:239-251`). Tasks R3-5, R3-7 and R3-9b test each.
- **DMA-queue stalls in a new order are not predictable** by an order-only rule (SR11b §2.3); at 0.069 ms each, eight more would be ≈7 % of the saving (`evidence/qwen9b/sr/SR16_R3_DECISION.md:172-175`). The placement band (SR11b) carries into R3-7.
- **VERSION is the launch tree's git hash** (`synth/scripts/launch_build.sh:12`): the build launches from a clean committed tree.
- **`evidence/qwen9b/g6/g6_state.py` has no VERSION check before its 155 MiB DMA** (`evidence/qwen9b/g6/g6_state.py:134`, `allow_seq=False`) until Task R3-0; until then the identity read immediately before it is the guard.

**B17.3's text** (spec §1.3 verbatim in substance):
- **Encoding.** MOVX `flags[7:4] = 0xF` = broadcast to channels 0..3; `flags[3:0]` stays `IND_NONE` (indirection refused, as today); `target[11:0]` = the XWIN start word **for all four** (B17.2's range rule, start word + ceil(len/4) ≤ 3072, applied to the one window); `addr_lo` / `len` as a unicast MOVX. `flags[7:4]` values 4..14 stay reserved (err 0x05); **MVGO `flags[7:4] = 0xF` stays err 0x05** (a broadcast is a MOVX only).
- **Semantics.** One scratch read, the same x written into each channel's XWIN at the same words (the census's "one scratch read, four XWIN writes", `evidence/qwen9b/ov/OV1_DEPENDENCY_CENSUS.md:633`). Retires only when every word is in every channel's XWIN FIFO (the same commit contract as the unicast burst, so the next MVGO's doorbell cannot overtake). **XPTR:** a unicast MOVX writes its channel's XPTR to 0 (`rtl/seq_movers.sv:904-905`); **a broadcast leaves all four XPTRs unchanged** (the push carries its word index) — architecturally visible through the XPTR readback and to the next AXI-Lite XWIN write, so host diagnostics must not assume XPTR = 0 after a broadcast.
- **Running rule** (B17.2's, per destination): a broadcast is INVALID if, for ANY channel c, its word range overlaps channel c's pending x range; the model gate and the pass's assert refuse it (no RTL interlock). Spec §1.3 says "the validator requires every destination channel's XWIN bank free"; as B17.2 splits it (`docs/SEQ_ISA.md` §B17.2, NO RTL INTERLOCK — RUNNING RANGES), the per-record validator is stateless and "the validator" here is the model gate plus the pass's assert — B17.3 and R3-2's gate doc say so (plan review m6).
- **Admission.** Validated only with {R1, R2, R3} ⊆ caps (the one bitstream that builds R3 also has R1 and R2; the validator names every missing capability). SEQ_CAPS on that bitstream = `seq_caps_word({"R1","R2","R3"})` = `0xFAB1CA07`.

- **Counters.** One mover job, `mv_op 0`: C6 counts the broadcast's window once (§B16).

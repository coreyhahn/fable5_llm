# Qwen3.5-2B V5 (W8 Everywhere) Implementation Plan — post gate D

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the 2B at the user-chosen V5 operating point — W8 g128 on all
matvec weights (PPL 12.361, ~16-17 tok/s) — via the W8 engine mode, the
per-channel DDR repack, the R-c artifact chain, and the R-d board bring-up,
ending with the qwen2b→main merge.

**Architecture:** The W8 wire law already exists and is selftested
(`ref/w4a8_ref.py`: `quantize_weights8`, `row_stride8`, pack/unpack) — the
RTL catches up to it exactly as R4 did for scale beats, with TB-vs-ref
bit-exactness as the arbiter. SHAPE bit 29 selects W8 per matvec run; `ng`
stays `K//128` (6-bit field), each ng unit = 2 physical weight beats in W8
mode. The DDR repack makes `plan_weights` nch-aware (per-channel image
bases + ILV-head chunk rebasing) with the 0.8B default provably
byte-identical. Then: 2B W8 images + streams, sim lockstep, build_035 with
the full phys_opt recipe, the 0.8B back-compat ladder, the 2B bring-up,
merge.

**Tech Stack:** SystemVerilog (Verilator 5.020 `-Wall --timing`), Python
numpy ref models, Vivado 2024.2 on snoke (`launch_build.sh` + the R8-era
`full_impl.tcl` recipe), BCU-1525 via the safe JTAG flow.

**Spec:** `docs/superpowers/specs/2026-08-12-qwen35-2b-migration-design.md`
(§Decision gate D, V4/V5 branch) + the gate-D decision record in
`NEXT_SESSION.md` (2026-08-16: V5 chosen; merge at R-d). Design basis for
the engine mode: `evidence/qwen2b/q2/v4_v5/W8_SKETCH.md`. Repack basis:
`evidence/qwen2b/q2/v4_v5/V4_V5.md` §5.
